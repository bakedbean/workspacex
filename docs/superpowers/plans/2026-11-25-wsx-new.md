# `wsx new` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One command that creates a workspace and reports success only once its agent is reachable from the Claude app and has the task.

**Architecture:** The foreground process parses and asks, writes a job file, and follows a detached worker (`setsid`). The worker creates the workspace, starts the agent through a running dashboard or, failing that, a headless `App` using the same launch code, waits for Claude's bridge id, then delivers the task.

**Tech Stack:** Rust, tokio, rusqlite, libc, portable-pty, tmux >= 3.2.

**Spec:** `docs/superpowers/specs/2026-11-25-wsx-new-design.md`

## Global Constraints

- Usage: `wsx new [--no-yolo] [--agent <kind>] [<repo> [task...]]`. Everything after the repo is the task, verbatim.
- Yolo by default outside a workspace; inside one, its mode is followed; `--no-yolo` always wins. Agent kind: `--agent`, else the parent's, else `coding_agent`.
- Always tmux-shared. `wsx workspace create` and dashboard behavior do not change.
- Claude reachability applies only when the agent is Claude and `remote_control` is on. No task is typed or enqueued before it passes.
- Timeouts: reachable 60s, delivery 120s, worker keeps watching 30 minutes after a reachability timeout.
- Fall back to headless only after a share request was withdrawn unclaimed.
- The worker never calls `drain_agent_messages`, `sweep_stale_pending` or `sweep_stale_running`.
- Headless delivery failure never enqueues. The task file is kept until delivery.
- Every command printed for the user is shell-quoted. In particular `tmux attach -t '=<session>'`: unquoted, zsh expands `=word`.
- Comments 2-4 lines at most. No Claude attribution in commits. No push.

## Review Focus

- A task containing `--help`, `-h` or `--no-yolo` after the repo is task text (Task 2).
- Ctrl-D or a closed stdin at either question exits 1 and creates nothing (Task 2).
- A session file whose `cwd` is spelled through a symlink (`/tmp` vs `/private/tmp`) still matches (Task 4).
- The agent renames its workspace before a failure is printed: the retry command uses the current slug (Task 6).
- `TERM` unset or `dumb` (an ssh command with no terminal): the tmux client still starts (Task 7).

## File Structure

- `src/cli/parse/new.rs`: arguments. `src/cli/new_prompt.rs`: repo ordering and questions.
- `src/agent/reachable.rs`: Claude session-file reader.
- `src/app/headless.rs`: `App` without sweeps, and the headless start.
- `src/commands/new/mod.rs`: job type and worker flow. `src/commands/new/detach.rs`: worker spawn and follower.
- Modified: `src/cli/{action,groups,help,run,mod}.rs`, `src/cli/parse/mod.rs`, `src/error.rs`, `src/commands/{mod,shared}.rs`, `src/app/{mod,state}.rs`, `src/agent/mod.rs`, `src/pty/tmux.rs`, docs.

### Task 1: Spike (throwaway, needs the user)

**Files:** none in the repo.

- [ ] **Step 1: Write a probe script in the scratchpad.** It creates a detached worktree of a registered repo, then runs, on a private server, `tmux -L wsxspike new-session -d -x 80 -y 24 -s p -c <worktree> -- claude --remote-control <mode flag>`. For 30s it polls `~/.claude/sessions/*.json` for that `cwd`, recording whether `bridgeSessionId` is set, then prints `tmux -L wsxspike capture-pane -p -t p`. It finishes with `kill-server` and `git worktree remove --force`. Run it once with `--dangerously-skip-permissions` and once without.

### Task 6: Worker flow

**Files:** Create `src/commands/new/mod.rs`; modify `src/commands/mod.rs`, `src/cli/run.rs`.

**Interfaces:**
- Consumes: Tasks 3-5; `data::workspace::create`; `enqueue_for_agent`, `shell_quote` (widen to `pub(crate)`).
- Produces: `Job { repo: String, yolo: bool, agent: String, task_file: Option<PathBuf> }` (serde).
- Produces: `trait Backend` with `start(&mut self) -> Result<Started>`, `alive()`, `screen()`, `reachable()`, `deliver(&mut self, task: &str) -> Result<Delivery>`. `Started` is `Dashboard | Headless`; `Delivery` is `Delivered | Queued | NotWritten`. The real one wraps the store and session; tests use a fake.
- Produces: `async fn drive(backend: &mut dyn Backend, opts: DriveOpts, report: &mut dyn FnMut(Event)) -> Outcome`. `DriveOpts` holds `needs_bridge`, the optional task, and the three timeouts. `Outcome` has one variant per row of the spec's outcome table.
- Produces: `async fn run_worker(job: &Path, dirs: &Dirs) -> Result<()>`.

- [ ] **Step 1: Write failing `drive` tests** with paused tokio time, one per row of the outcome table, plus:
  - `deliver` is never called before `reachable()` is true when `needs_bridge`; it is called straight away when not.
  - Reachability times out at 60s: the outcome is reported then, and a bridge at 5 minutes still delivers exactly once. Nothing by 60s + 30min: it ends without delivering.
  - The agent dies before reachable: reported at once, with the last non-blank screen seen.
  - Headless `NotWritten`: one `deliver` call, no enqueue, retry command reported. Dashboard `Queued`: the output says it is still queued.
- [ ] **Step 2: Write failing message tests:** the retry command is `wsx agent send --workspace <repo>/<slug> --file <task file> primary`, shell-quoted, with the slug read from the store by id at print time (rename the row first in the test). The attach command is `tmux attach -t '=<session>'`.
- [ ] **Step 3: Write a failing start test:** `NoDashboard` goes headless; any other share error is reported with no headless attempt. A failed setup script warns and still starts.
- [ ] **Step 4: Run** `cargo test --lib commands::new`; fail.
- [ ] **Step 5: Implement.** Poll every 500ms. Dashboard delivery enqueues once, then polls `message_by_id` until `reached_agent()`; a set `drop_reason` is not delivered. Headless delivery is `send_text_when_settled(task, DELIVERY_QUIET_MS, DELIVERY_TIMEOUT_MS)` with no banner. Hold the session until `drive` ends. Remove the task file only after `Delivered`.
- [ ] **Step 6: Run**; pass. **Step 7: Commit** `Drive wsx new from creation to a delivered task`.

### Task 7: Detach and follow

**Files:** Create `src/commands/new/detach.rs`; modify `src/cli/run.rs`.

**Interfaces:**
- Consumes: `Job`, `run_worker`, `new_prompt`.
- Produces: `detach::spawn(exe: &Path, args: &[OsString], log: &Path) -> Result<Child>` (stdin null, output to `log`, `setsid` in `pre_exec`) and `detach::follow(log: &Path, exit_file: &Path, alive: &mut dyn FnMut() -> bool, out: &mut dyn Write) -> Result<i32>`.
- Produces (macOS, from the spike): `detach::plist(label, args, env, log) -> String` (RunAtLoad, AbandonProcessGroup, XML-escaped) and `detach::spawn_in_gui(...)`, used when `launchctl managername` is not `Aqua`; on failure warn and use `spawn`. The plist is mode 0600 and removed after bootstrap. The environment drops `SSH_*`. The worker boots out its label last. Test: `plist` escapes `&<>` and `plutil -lint` accepts it; the environment helper drops `SSH_*`.
- The worker writes its exit code to `<log>.exit` by temp file and rename, after the outcome's output. The follower drains the log, then returns that code; if the worker dies without writing it, it drains, prints the log path and returns 1.

- [ ] **Step 1: Write failing tests** using `/bin/sh` workers:
  - The child's session id (`libc::getsid`) differs from the test's.
  - The worker finishes a file write after its parent shell gets SIGHUP.
  - `follow` copies all output including non-UTF-8 bytes, returns 0 and 1 from the exit file, returns while the worker is still running once the file exists, and returns 1 on a worker killed first.
  - The worker environment helper sets `TERM=xterm-256color` when unset or `dumb`, keeps any other value, and removes `CLAUDECODE`, `CLAUDE_CODE_SESSION_ID` and `CLAUDE_CODE_ENTRYPOINT` (a launching agent's identity must not reach the new one).
- [ ] **Step 2: Run** `cargo test --lib commands::new::detach`; fail. **Step 3: Implement.**
- [ ] **Step 4: Wire `CliAction::New`:** no repo and stdin not a terminal is a usage error. Resolve yolo and agent in the foreground. Check the repo (`lookup_repo`), `tmux::is_available()` and `missing_agent_binary` before spawning. Warn if Claude with `remote_control` off. Write job, task and log under `dirs.log_dir()/new/` with a unique stem and mode 0600. `Error::Cancelled` exits 1 quietly. Exit with the follower's code without printing a second error.
- [ ] **Step 5: Write and run a CLI test** that an unknown repo and a missing tmux (`WSX_TMUX_BIN=/nonexistent`) each fail with no workspace row.
- [ ] **Step 6: Run** `cargo test` and `cargo clippy --all-targets -- -D warnings`; clean. **Step 7: Commit** `Add wsx new, detached from its terminal`.
